# CMS方針メモ

最終更新: 2026-09-16

## 背景

このリポジトリは、Astroで作ったシンプルなブログ／小規模サイトを配布・運用するためのテンプレートである。

CMSについて検討した当初の目的は、開発者自身のための高機能な管理画面を追加することではなく、**サイト構築後に、GitHubやMarkdownを知らない一般の利用者でも記事や画像を簡単に更新できる仕組みを用意できるか**を確認することだった。

その検討の一環として、既存のGitベースCMSを調査し、Sveltia CMSをこのテンプレートへ載せる実験を行った。

## 今回確認した既存CMS

### Sveltia CMS

- Astro + GitHub上のMarkdownとの相性は良い。
- `/admin/` のような薄い管理画面を追加しやすい。
- 日本語UIが利用できる。
- CMS本体は無料・OSSで、追加のnpm依存をほぼ増やさず利用できる。
- 一方、GitHubバックエンドではPATまたはOAuth等の認証が必要であり、**GitHubを知らない一般利用者へそのまま渡すには少し重い**。

### Pages CMS

- GitHub上のMarkdownや画像をGUIから編集する用途に近い。
- 一般の編集者をメールで招待でき、GitHubアカウントを要求しない運用が可能。
- 「既存OSSを利用して非技術者向け編集画面を提供する」という目的にはかなり近い候補。
- 今後、実際に採用を検討する時点で、日本語UI、運用条件、セルフホスト可否、認証・権限まわりを改めて確認する。

### その他

Keystatic、Decap CMS、Front Matter CMSなども候補になりうるが、このテンプレートに必要なのは高機能CMSではなく、**記事・画像更新だけを簡単にする薄い仕組み**である。

## 欲しい利用体験

将来的にCMSを搭載する場合、理想は次のようなもの。

1. 開発者がAstroサイトを構築・デプロイする。
2. サイト内の `/admin/` などへ更新画面を用意する。
3. サイト管理者にはURLと簡単な認証情報だけを渡す。
4. 管理者はGitHub、Git、Markdown、PAT、OAuth等を意識せず記事や画像を更新できる。
5. 保存された内容はMarkdown等のポータブルな形式としてリポジトリへ残る。
6. Git連携されたホスティングが自動で再ビルド・再デプロイする。

重要なのは、「CMSを使うためにCMSを学ぶ」状態を避けること。

## 独自CMS案

既存CMSでこの利用体験を十分に満たせない場合は、Astro向けのごく薄いCMSを独自実装する余地がある。

想定する最小構成は次の通り。

- `/admin/` にログイン画面と記事編集画面
- 共有パスワード等による非常に単純な認証
- サーバー側APIからGitHub等へMarkdownを保存
- 画像アップロード
- frontmatterの編集
- 記事一覧、新規作成、編集、削除
- GitHubのcredentialはブラウザへ露出させない

### 共有パスワード方式について

「サイト構築時にパスワードを1つ発行し、そのパスワードを知る人だけ更新できる」という方式は、小規模サイトでは使いやすい可能性がある。

ただし、以下の制約がある。

- 編集者ごとの識別ができない。
- 一人だけ権限を剥奪できない。
- パスワード漏洩時は全員分を変更する必要がある。
- 権限管理や監査ログには向かない。

採用する場合でも、パスワードを静的HTMLやクライアントJavaScriptへ埋め込まず、サーバー側Secretとして保持する。また、セッションCookie、rate limit、CSRF対策、書き込み先制限、frontmatter validation等の基本的な対策は必要。

これはWordPressのような多機能CMSを目指すものではなく、**小規模なAstroサイトに組み込める「共有パスワード式の薄い編集パネル」**として考える。

## 現時点の判断

**今すぐ独自CMSを実装しない。**

Sveltia CMSの実験は、既存CMSの使い勝手と制約を知るための検証として扱う。特定CMSの正式採用を決定したわけではない。

将来、このテンプレートや実案件で「非技術者が自分で更新できるCMS」が実際に必要になった時点で、次の順序で判断する。

1. その時点で利用できる既存CMSを再調査する。
2. 十分にシンプルで、日本語利用や非技術者運用に適したCMSがあれば採用する。
3. 適切なものがなければ、上記の最小要件をもとに独自CMSを実装する。

CMSはこのテンプレートの必須機能とはせず、必要になるまではMarkdown直編集によるシンプルな構成を維持する。
